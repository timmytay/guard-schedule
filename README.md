# График охраны

Локальная информационная система для диспетчера и охранников. Приложение использует Python 3.11+, Django, SQLite и русскоязычный адаптивный интерфейс. Для просмотра назначений доступен API Django REST Framework с документацией OpenAPI.

## Запуск демонстрации

В каталоге проекта выполните команды. В Windows используйте `.venv\Scripts\activate` вместо команды активации ниже.

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py duty_demo
python manage.py runserver 127.0.0.1:8000
```

Откройте http://127.0.0.1:8000. Вход диспетчера — `dispatcher`, вход охранника — `guard01`. Демонстрационный пароль для обеих ролей — `Demo-duty-2601!`. Команда создаёт 25 охранников, три объекта, историю дежурств за две недели, утверждённый график и будущий черновик, отчёты в четырёх статусах, зарегистрированные отсутствия и уведомления.

## Сценарии

- В кабинете диспетчера сформируйте график на другой будущий месяц. Скачайте PDF и утвердите график после подписи руководителя.
- В разделе «Замены» зарегистрируйте больничный. Откройте затронутую позицию и выберите кандидата. Между сменами учитывается время отдыха с обеих сторон. Для стандартного назначения требуется 72 часа, для подтверждённой экстренной замены — 24 часа. Сутки смены начинаются в 08:00 по Иркутску. Даты отсутствия включительны.
- Войдите как `guard01`. Откройте расписание за дату учебной завершённой смены или выберите прошлый период через поле «Период». Заполните отметки о приёме-передаче и отправьте отчёт. Затем в кабинете диспетчера утвердите отчёт или верните его с комментарием.
- В разделе «Уведомления» подтвердите получение сообщения. Диспетчер может повторить уведомление и выгрузить отфильтрованный список отчётов в CSV.
- Документация к API назначений доступна по адресу `/api/docs/`.

## Настройка эксплуатации

Создайте новую базу через `python manage.py migrate`. Для первой учётной записи запустите `python manage.py createsuperuser` и установите ей признак диспетчера.

```sh
python manage.py shell -c 'from duty.models import User; User.objects.filter(username="dispatcher").update(dispatcher=True)'
```

Для сервера задайте `DUTY_DEBUG=0`, уникальный `DUTY_SECRET_KEY`, список доменов в `DUTY_HOSTS` и путь к базе в `DUTY_DATABASE`. Запустите WSGI-приложение `duty.wsgi:application` за HTTPS-прокси, который перезаписывает заголовок `X-Forwarded-Proto`. Выполните `python manage.py collectstatic` и настройте прокси на выдачу каталога `staticfiles` по адресу `/static/`. Встроенный HTTP-сервер предназначен для локальной демонстрации на loopback-адресе.

- Запускайте `python manage.py duty_tick` раз в минуту через планировщик, исключив одновременный запуск двух экземпляров. Команда обрабатывает напоминания и почтовую очередь. Для SMTP задайте `DUTY_SMTP_HOST`, `DUTY_SMTP_PORT`, `DUTY_SMTP_USER`, `DUTY_SMTP_PASSWORD` и `DUTY_EMAIL_FROM`. Кабинет отображает приём письма SMTP-сервером или ошибку отправки после повторной попытки. Подтверждение получения выполняется в кабинете.
- Запускайте `python manage.py duty_backup /путь/к/внешнему/хранилищу` ежедневно и настройте хранение копий минимум 30 дней. Для восстановления остановите приложение, сохраните текущую базу и её служебные файлы, скопируйте проверенную резервную копию на новый путь, задайте этот путь в `DUTY_DATABASE` и запустите приложение.

Месячное распределение использует поиск по доступным сотрудникам с учётом соседних назначений и отсутствий. При недостатке охранников форма генерации выводит проблемные даты, а черновик не сохраняется. Маршрут POST `/api/schedule/generate/` принимает JSON с полями `month` и `year`. Алгоритм не доказывает оптимальность распределения.

SMS, браузерный Push, отдельная архивация старых записей и полный API записи не реализованы. Настройка HTTPS, проверка реального SMTP, нагрузочная проверка и подтверждение эксплуатационной доступности относятся к развёртыванию.

## Клиентская часть и тестирование

Vue 3 и Vuetify загружаются уже на странице входа. Исходники страниц авторизации,
главной, расписания и журнала находятся в `frontend/src`. Поставляемая сборка
находится в `duty/static/vue`, поэтому обычный запуск Django не требует Node.js.
Формы подбора замены, справочников, отсутствий, отчётов и уведомлений пока
формирует Django.

После изменения Vue-компонентов пересоберите клиент из каталога `frontend`
с Node.js 20.19+ или 22.12+:

```sh
npm ci
npm run build
```

Из корня проекта выполните модульные тесты расчёта отдыха и отсутствий и
функциональные тесты Django:

```sh
python manage.py test duty.tests.AvailabilityUnitTests
python manage.py test duty.tests.GenerateScheduleTests duty.tests.DomainRelationsTests duty.tests.DispatcherInterfaceTests
```

Для интерфейсных тестов запустите сервер с демонстрационной базой по инструкции
выше. Из каталога `frontend` выполните:

```sh
npx playwright install chromium
npm run test:ui
```

По умолчанию Playwright обращается к `http://127.0.0.1:8000`. Для другого
адреса задайте `DUTY_UI_BASE_URL`. Для установленного Chromium можно задать
путь к исполняемому файлу в `DUTY_CHROMIUM`.


## Готовая демонстрационная база из ZIP

Если рядом с `manage.py` лежит `demo.sqlite3`, укажи её перед запуском сервера.

PowerShell:
```powershell
$env:DUTY_DATABASE = "demo.sqlite3"
python manage.py runserver
```

macOS или Linux:
```sh
DUTY_DATABASE=demo.sqlite3 python manage.py runserver
```

Демоучётные записи: `dispatcher` и `guard01`, пароль для обеих учёток —
`Demo-duty-2601!`. Для новых дат запусти `migrate` и `duty_demo` с путём
к новой пустой базе. Команда не подмешивает демоданные в действующую базу.
